# このアプリの作り方 — 実際に使ったプロンプト

好きな場所Bot は、Claude Code に短いプロンプトを渡し、仕様駆動（requirements → design → tasks → 実装、各段階で人が承認）で作りました。ここには、アプリに関わるプロンプトを**打ったままの文面で**、日付と使ったモデル付きで載せます。アプリと関係のないやり取り（PR の分割やメモの書き出しなど）は省いています。

## 進め方

```
短いプロンプト（数行）
  → requirements（何を作るか。受け入れ基準を EARS 形式で）   … 人が確認して承認
  → design（どう作るか。DB・状態遷移・セキュリティ）          … 人が確認して承認
  → tasks（作業の分解）                                        … 人が確認して承認
  → 実装とテスト
  → 動かして気づいたことを、また短いプロンプトで伝える
```

仕様は開発中だけファイルとして置き、実装はそれに従わせました。要望が変わったときは、コードではなく仕様を先に直します（完成後、確定した内容は README の「しくみ」とコードのコメントに移しています）。

## AI が間違えて、人が直したところ

| 起きたこと | 原因 | 気づいたきっかけ | 直し方 |
|---|---|---|---|
| LIFF が「読み込み中」のまま動かない | 固定の Content Security Policy が、Next.js が埋め込むインラインスクリプトを止めていた | 実機で開いて、コンソールのエラーを貼った | リクエストごとに nonce を発行する `src/proxy.ts` に変更 |
| デプロイしたら全ページ 404 | CLI で作った Vercel プロジェクトの framework が「Other」になっていた | デプロイ後に URL を叩いて確認した | `vercel.json` で `"framework": "nextjs"` を明示 |
| `LINE_CHANNEL_ID` にどの ID を入れるか迷う | 説明が Messaging API チャネルの欄に書かれていた | キーを発行する段階で迷った | LIFF を置いたチャネルの ID だと `env.sample` に明記 |
| 「登録」なしで位置情報を送っても何も返らない | 実装（noop）が requirements（案内を返す）とずれていた | モックと照らし合わせた | 状態遷移に `location_guide` を追加 |

## 読者が作り直すなら

1. 上の「1回目」のプロンプトから始め、requirements → design → tasks の各段階で中身を確認してから次へ進むよう AI に頼む
2. 完了条件は「`npm test`（状態遷移・Quick Reply・リッチメニューのテスト）と `npm run build` が通ること」
3. 生成されるコードは毎回少しずつ違います。README の「しくみ」にある状態遷移・署名の確認・IDトークンの検証・RLS に当たる処理があるかを確かめてください
